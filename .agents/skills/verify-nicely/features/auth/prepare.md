# Prepare and inspect the key

Part of [auth](../auth.md). Follow the three guides in order.


Preconditions:

- A new run from `just verify`, whose Doctor step passed. On macOS, an agent runs it as Gotchas says
- `tmux -V` answers, for the steps in a terminal, as [terminal.md](terminal.md) describes `just verify tmux`
- The keychain may hold the fake key of an earlier run under `verifynicely`, left by a release without logout or by a cleanup that could not finish
- The fake key of this run: `fake=verify-nicely-fake-$(date +%s)`

- **No default keychain.** On macOS, before the step Fixture, run `just verify step "$run" auth auth status --json`. Exit 0 with `"keychain":"unavailable"`: the scratch home holds no keychain. Then `printf '%s\n' "$fake" | just verify step "$run" auth auth login verifynicely --stdin --json` exits 78 with `KEYRING_UNAVAILABLE`, and no window opens.
- **Fixture.** Run `just verify prepare "$run" auth`, with `--mac-keychain` on macOS. Exit 0, and stderr names the service `verifynicely` and its variable `VERIFYNICELY_API_KEY`, and on macOS that the wrapper keeps the real `HOME`.
- **Help.** Run `just verify step "$run" auth auth --help`. Exit 0, and `COMMANDS` lists `grant`, `login`, `logout`, `revoke`, and `status`.
- **Grant dry run.** Run `just verify step "$run" auth auth grant verifynicely verifykeys --dry-run --json`. Exit 0, and stdout is `{"ok":true,"contract_version":1,"dry_run":true,"pending_checks":[{"id":"auth.confirmation","message":"Whether a human at a terminal confirms the grant of the key of verifynicely to verifykeys."}],"plan":[{"key":"verifynicely","action":"grant","domain":"verifykeys","effects":{"user_writes":true,"network":false,"paid":false}}]}`.
- **Grant without a terminal.** Run `just verify step "$run" auth auth grant verifynicely verifykeys --json`. Exit 78, stdout is empty, and stderr ends with an answer whose first error is `TERMINAL_REQUIRED`, with the hint ``Run `ncly auth grant verifynicely verifykeys` in a terminal`` and the `next` `["ncly","auth","grant","verifynicely","verifykeys"]`.
- **No grant to revoke.** Run `just verify step "$run" auth auth revoke verifynicely verifykeys --force --json`. Exit 2, and stderr ends with an answer whose first error is `NOT_FOUND`, with the hint `ncly auth status` and the same command in `next`.
- **Missing key.** Run `VERIFYNICELY_API_KEY= just verify step "$run" auth auth status --json`. Exit 78, stderr is empty, and stdout is one line with `"ok":false`, `"keychain":"available"`, and one entry, whose `grants` is `[{"domain":"verifykeys","granted":false,"optional":false}]`. Without the fake key of an earlier run, the entry is `{"service":"verifynicely","configured":false,"source":"none","code":"AUTH_MISSING", ...}`, whose `hint` is `ncly auth login verifynicely` and whose `next` is `["ncly","auth","login","verifynicely"]`: a missing key reports its own code alone, without its grant. With it, the entry is `{"service":"verifynicely","configured":true,"source":"keychain","code":"KEY_NOT_GRANTED", ...}`, as in the step Key from the keychain: report which one you saw.
- **Missing key as text.** Run `VERIFYNICELY_API_KEY= just verify step "$run" auth auth status`. Exit 78. The first line is `keychain      available`, then an empty line. Without the fake key of an earlier run, the line of `verifynicely` is `verifynicely  none  verifykeys: not granted`. Two lines follow it, in the column of `none`: `fail[AUTH_MISSING] No key for verifynicely in VERIFYNICELY_API_KEY or the keychain.`, then `hint: ncly auth login verifynicely`. With the key, the line is `verifynicely  keychain  verifykeys: not granted`, and the two lines are `fail[KEY_NOT_GRANTED] The key of verifynicely is not granted to verifykeys.`, then `hint: ncly auth grant verifynicely verifykeys`.
- **Key from the variable.** Run `VERIFYNICELY_API_KEY="$fake" just verify step "$run" auth auth status --json`. Exit 78, and stdout is `{"ok":false,"contract_version":1,"keychain":"available","services":[{"service":"verifynicely","configured":true,"source":"env","code":"KEY_NOT_GRANTED","message":"The key of verifynicely is not granted to verifykeys.","hint":"ncly auth grant verifynicely verifykeys","next":["ncly","auth","grant","verifynicely","verifykeys"],"grants":[{"domain":"verifykeys","granted":false,"optional":false}]}]}`: the key is there, and no human granted it to the fixture yet.
- **Login dry run.** Run `just verify step "$run" auth auth login verifynicely --dry-run --json`. Exit 0, and stdout holds `"dry_run":true`, the plan `{"key":"verifynicely","action":"login","effects":{"user_writes":true,"network":false,"paid":false}}`, and the pending check `auth.keychain`.
- **Login.** Run `printf '%s\n' "$fake" | just verify step "$run" auth auth login verifynicely --stdin --force --json`. Exit 0, and stdout is `{"ok":true,"contract_version":1,"action":"login","service":"verifynicely"}`.
- **Key from the keychain.** Run `VERIFYNICELY_API_KEY= just verify step "$run" auth auth status --json`. Exit 78, and stdout is the one of the step Key from the variable, with `"source":"keychain"` instead of `"source":"env"`.
- **Doctor without the grant.** Run `VERIFYNICELY_API_KEY= just verify step "$run" auth doctor auth --json`. Exit 78, stderr is empty, and stdout is `{"ok":false,"contract_version":1,"checks":[{"id":"auth.keychain","component":"auth","status":"pass","message":"The keychain answers."},{"id":"auth.grants","component":"auth","status":"pass","message":"Every grant is in use."},{"id":"auth.verifynicely","component":"auth","status":"fail","code":"KEY_NOT_GRANTED","message":"The key of verifynicely is not granted to verifykeys.","hint":"ncly auth grant verifynicely verifykeys","next":["ncly","auth","grant","verifynicely","verifykeys"]}]}`.
- **Fixture without a grant.** Run `VERIFYNICELY_API_KEY= just verify step "$run" auth verifykeys digest --json`. Exit 78, stdout is empty, and stderr is one line, an answer whose first error is `KEY_NOT_GRANTED`, with the hint `ncly auth grant verifynicely verifykeys` and the same command in `next`: the keychain holds the fake key, and still it does not reach the fixture.
