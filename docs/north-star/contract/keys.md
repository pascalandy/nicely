# Keys

- A service has a name of lowercase letters and digits that starts with a letter, such as `deepgram`, other than `keychain` and `grants`, which name the checks of the keychain and of the grants in [ncly doctor](../core-spec.md#required-keys). Its environment variable is the name in uppercase followed by `_API_KEY`, such as `DEEPGRAM_API_KEY`. An extension declares the services that each command needs in the `requires.keys` of its [manifest](manifest.md).
- Core reads a key from its environment variable first. It reads the key from the keychain only when that variable is empty, and only for a command whose declaration needs the key and an extension that a human granted it to, as [Grants](grants.md) defines. A dry run reads no key. `ncly auth` and `ncly doctor` also check the keychain. The keychain entry uses the service `nicely` and the account named after the service.
- Each keychain call has a time limit: 60 seconds in interactive mode, where a human can answer an unlock prompt, and 10 seconds otherwise. A keychain that does not answer a read in time counts as unavailable. Once a call finds the keychain unavailable, the command asks it nothing more and counts it unavailable for every later key, so a command that reads several keys waits for one limit at most. A command that needs a key exits 78 with `KEYRING_UNAVAILABLE` when the key is missing from the environment and the keychain is unavailable, and its hint names the variable to export. When the keychain answers without the key, the code is `AUTH_MISSING`.
- `KEYRING_UNAVAILABLE` names a keychain that fails before any write. A write, the `Set` of `ncly auth login` or the `Delete` of `ncly auth logout`, that fails or gets no answer within its limit has an unknown effect, because the keychain may still store or remove the key after `ncly` answers. The command then exits 1 with `RUNTIME`, as [Retry safety](retry-safety.md) requires, with a hint that asks the human to check `ncly auth status`, and that command as its `next`. A service missing from that report proves nothing about its key, so for a service that no installed extension declares, the hint sends the human to Nicely's entry in the OS keychain.
- A key is never accepted as a flag. In a terminal, `ncly auth login` reads it in the masked field that [Modes](modes.md) describes, which never shows it. With `--stdin`, it reads the key from stdin.
- A key is never printed. `ncly auth status` reports where a key comes from, never its value.
