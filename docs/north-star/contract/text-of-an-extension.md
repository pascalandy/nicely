# Text of an extension

An extension keeps its text in catalogs, in the format of core's: one TOML file per language, named after its language tag, such as `en.toml` or `fr-CA.toml`, whose entries each have a description for the translator. An external extension's catalogs sit in `ncly-<domain>.locales/` beside its manifest, and a first-party extension keeps them in `extensions/<name>/locales/`. The `en` catalog is required. The files list the languages that the extension speaks, so the manifest declares none, and a translation that cannot be read is skipped, so its entries fall back to `en`.

Core renders an extension's help and completion descriptions from its manifest and catalogs, so help never starts it. `NCLY_LANG` carries the requested language as a language tag, such as `fr-CA` for `LANG=fr_CA.UTF-8`, and `en` when no source names a known language, as for `C` or `POSIX`. Core and each extension then pick their own closest catalog with the rule of [Configuration](configuration.md), falling back to `en` independently: a French request shows core in French and an extension that speaks only English in English. An entry that a catalog lacks falls back to its `en` entry. Under the pseudo-locale `en-XA`, core marks the text of an extension's `en` catalog as it marks its own.
