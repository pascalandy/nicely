# Programs that ncly runs

Core runs extensions, including the commands that it calls itself, as [Commands that core calls](commands-that-core-calls.md) defines, and doctor's version probes. An extension runs its own programs, such as transcript's Python program or a harness that the `agent` extension starts, through the SDK's program runner, which follows the same rules. None of them runs in a sandbox. A program runs with the rights of the user, so it could read the keychain or any file itself. Adding a tap or installing an extension means trusting its author.

One program starts outside the program runner. On macOS, go-keyring, which `internal/keychain` wraps for [Keys](keys.md), starts `/usr/bin/security` itself, and passes it a key on its stdin, never in its arguments. That program therefore has no process group of its own, no timeout from the runner, and no pipes that the runner owns. The keychain sits at layer 0, below the runner, and a write that it abandons at its limit keeps an unknown effect whether or not something stops `security`, as Keys defines, so the runner would make no call safer. Cancellation still reaches `security` through its parent process, as it reaches every descendant, and a signal during a write keeps exit 130 or 143 with an effect that stays unknown. The exception covers this one program, never a `security` that an extension starts.

**Workers.** A worker is a program that an extension embeds in its executable, such as a user's Bash or Python script. It keeps its own language, and its interpreter, such as `uv` or `bash`, is a declared program. The SDK extracts it for each run, as [SDK](sdk.md) defines. The extension runs it as it runs any declared program. Its Go handler maps the worker's exit code and output into this contract, as [Wrapped programs](wrap.md) defines. A program that the machine already has, such as `glow`, is declared, and nothing embeds it.

**Environment.** A program receives the environment of its parent with these changes:

- Each variable named `<NAME>_API_KEY` is the key of a service. An extension receives it only when a human granted that key to it, and core then sets it from the environment or the keychain, and `NCLY_MISSING_KEYS` names each declared key that it does not receive, as [Grants](grants.md) defines. An extension passes a key on only to the program that its spec names, such as `DEEPGRAM_API_KEY` to transcript's Python program
- The variables of the global flags carry their resolved values: `NCLY_JSON`, `NCLY_NO_INPUT`, and `NCLY_VERBOSE` equal `1` when their flag resolves on and are removed otherwise, `NO_COLOR` equals `1` when color resolves off and is removed otherwise, and `NCLY_LANG` holds the requested language tag, as [Text of an extension](text-of-an-extension.md) defines. `NCLY_DEBUG` passes unchanged. `NCLY_VERSION` and `NCLY_CONTRACT_VERSION` identify the release and public protocol.
- `NCLY_BIN` holds the absolute path of the running `ncly`, so that a program calls another domain through the same host, as cargo passes `CARGO` to its subcommands
- A harness receives `NCLY_AGENT_DEPTH` plus one, as the [agent extension](../../../extensions/agent/spec.md#depth-limit) defines

**Process groups.** The program runner starts each program without the terminal in a new session, which gives it its own process group and no controlling terminal. A Ctrl-C at the terminal therefore reaches `ncly` alone, and the runner signals the program. A read of the terminal, such as an open of `/dev/tty`, fails at once, instead of stopping the program until its timeout. Such a program also gets no descriptor of the terminal. The runner refuses a terminal on its stdin, and copies its stdout and stderr to the terminal through pipes. This one rule covers a worker, doctor's version probes, and the commands that core calls, as [Commands that core calls](commands-that-core-calls.md) defines. A program that may read the terminal stays in the process group of `ncly` instead: an extension, which asks through its forms. A process outside the terminal's foreground group stops when it reads the terminal, as [D047](../decisions/D047-terminal-process-group.md) explains. A program can therefore receive the same signal more than once, from the terminal, from `ncly`, and from the extension that started it, and it treats a repeat during its cleanup as no new event.

**Cancellation.** On Ctrl-C or SIGTERM, `ncly` sends the signal to every program it started and to every descendant that it can still reach. It sends SIGKILL to what still runs 15 seconds later, which leaves a Python program its own 10 seconds to stop its children. A list command that completion runs gets SIGKILL at once instead, as [Completion values](completion-values.md) defines. Before each signal, `ncly` finds descendants through their parent process, so a descendant that left the process group of its parent, as the children of transcript's Python program do, still receives the signal. On Linux, `ncly` registers as a child subreaper, so it also reaches a descendant whose parent already exited. macOS has no subreaper, so a descendant whose parent exited before the signal is the one exception there, and it keeps running. `ncly` keeps every finished output and removes only its own temporary files. It exits 130 with `INTERRUPTED` or 143 with `TERMINATED`, and under `--json` the answer keeps the data keys that apply, such as `output_dir` or the `results` of finished items. A second signal during this cleanup is ignored. A SIGKILL sent to `ncly` itself leaves no time to clean up.

**Output streams.** A descendant that inherits a program's stdout or stderr can hold it open after the program exits, as an orphan on macOS can. `ncly` stops reading the streams that it reads from a program 2 seconds after that program exits, including the exit that the SIGKILL of cleanup forces. A descendant therefore never keeps `ncly` waiting, and output written after that point is lost. This drain limit is its own clock, apart from the 15 seconds of cleanup. Doctor's version probes and `sdk/wrap` keep only the first bytes of each stream, up to a limit, so a noisy program never fills memory. When its limit ends a command that core calls, core closes its pipes at once, without a drain limit, as [Commands that core calls](commands-that-core-calls.md) defines. Doctor does the same for a version probe that it kills at its limit. A list command that completion runs gets no drain limit in any case, because its 2 seconds bound the reading too, as [Completion values](completion-values.md) defines. A stream that `ncly` passes on without reading, such as an extension's stdout without `--json`, stays with the descendant, which may still write to the terminal after `ncly` exits.

**Normal end.** An extension answers only after every program that it started has ended, except a viewer that it starts detached for the user, such as the folder that transcript's `--open` shows. The SDK's program runner waits for each program that it started. When a program ends normally while a descendant still runs, `ncly` neither waits for that descendant nor stops it, because it cannot tell a forgotten program from a window that the user keeps open. The output stream rule keeps such a descendant from blocking `ncly`.

**Timeout.** The timeout covers the command's work and starts before child execution. On expiry, use the same process-tree cleanup as cancellation, except in two cases. Core kills a command that core calls at once, as [Commands that core calls](commands-that-core-calls.md) defines. Doctor kills a version probe at once, as [ncly doctor](../core-spec.md#ncly-doctor) defines. A temporary failure before any paid request exits 75 only when Retry safety holds. Otherwise it exits 1. A caller's SIGTERM remains exit 143. Record finished work and unknown effects before returning when the process can still do so.

**Protocol failures.** An extension answers core as any command answers its caller, and core checks it as [Answer check](answer-check.md) defines. A Python program in Nicely's own code, such as transcript's, returns versioned machine messages only, which its extension's Go code maps into this contract. A worker has no such protocol: its handler maps its exit code and its output, and its own exit 75 never makes a repeat safe. Missing, malformed, or incompatible messages never count as success. A launched program may already have produced effects, so preserve available evidence and use a runtime failure unless safety can be established. Harness adapters declare the modes they can actually enforce. An unsupported tools-off mode fails with `CAPABILITY_UNSUPPORTED` before launching the task.
