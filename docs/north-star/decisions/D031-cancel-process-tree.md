# D031 Stop the whole process tree on cancel and keep finished work

Decided 2026-10-05. On Ctrl-C or SIGTERM, `ncly` stops every program it started and every descendant that it can still reach, orphans included on Linux, keeps every finished output, and exits 130 or 143 with the data that still applies, as [contract.md](../contract.md#programs-that-ncly-runs) defines. Run inspection distinguishes verified finished work from uncertain effects. Neither interruption code authorizes an automatic retry. `ncly` stops reading a program's output streams 2 seconds after that program exits, or at the SIGKILL of cleanup, so a descendant that holds them open never keeps `ncly` waiting. After a normal end, an extension has waited for the programs it started, and `ncly` neither waits for nor stops a descendant that remains.

**Why.** The transcript CLI starts its children in their own process groups, so a signal to its parent alone leaves `yt-dlp`, `ffmpeg`, or a harness running. A harness that hits its time limit sends SIGTERM. A finished transcript may already be billed, so cleanup must never delete it.

`ncly` finds descendants through their parent process, because a signal to a process group misses the children that the transcript CLI starts in their own sessions. On Linux, `ncly` registers as a child subreaper, so an orphaned descendant stays reachable. macOS has no equivalent, so a descendant whose parent exited before the signal is the one exception there. A descendant that inherited a pipe keeps it open until it exits, so reading every stream to its end could wait forever on that exception. Two seconds leave time to read what the program wrote before it exited. A descendant that remains after a normal end may be a window that the user keeps open, such as the folder that `--open` shows, so only the extension that started a program knows whether to wait for it.

**Rejected.** Signaling only the direct child, which is what Go's `exec.CommandContext` does by default. Reading every output stream to its end. Waiting for every descendant after a normal end, as Asupersync's regions wait for their tasks, which would block on a viewer that `--open` starts. Stopping every descendant after a normal end, which would close that viewer. Relying on the Python program alone to stop its children, because the SIGKILL after 15 seconds leaves them running. Deleting partial results on interrupt. Assuming a stopped process proves that its last external request had no effect.
