# D052 Let the caller name a run, so that a repeated call continues it

Decided 2026-10-12, revised 2026-10-16. A recorded command accepts `--run-id <id>`. A call whose ID no record holds starts a run under that ID. A call whose ID a record holds starts nothing new: it returns the saved result of a completed run, continues the run as `ncly run resume` would when the command supports resume, runs every step again when each step whose intent the run persisted declares `none` or `repeatable`, both in the record and now, and otherwise answers `RESUME_UNSAFE`. A call compares only what it states, its command path, its inputs, and the ordered keys of the items that it names, with a file or a text by its fingerprint and a folder by its absolute path, and a difference fails with `USAGE_INVALID`. What preparation picked from the config or the machine, such as the actual model and effort under `resolved`, is never part of that comparison, and every later attempt reads it from the record. A repeated call returns the first call's result: a successful answer comes from the committed record and its artifacts, prints only after the completion write, and follows the flags of the call that prints it, while a step's evidence keeps any answer value that neither holds. A step that starts a recorded command for its own work persists the child's ID with its intent, before the call, and repeats the call only while the child's record exists. [Run IDs](../contract.md#run-ids) holds the rules.

**Scope update, 2026-10-17.** M10 and M13 first implement one item and one paid step. They must persist intent, return verified completion, reject changed stated inputs, and refuse uncertain paid effects. The contract branches for explicit resume, child-run recovery, and changing effect policies stay with their future consumers in [M99](../../milestones/M99-parking-lot.md#resume). They require no generic fixtures or executor in the first implementation.

**Why.** An agent's shell can kill `ncly` or lose its answer, and the answer held the only copy of the run ID. Recovery then meant searching `ncly run list` by command path, item key, and start time, and a fresh session could find several candidates or none. A caller that chose the ID before the call still knows it after any loss: `ncly run view <id>` finds the run at once, and repeating the same call is safe, because the record decides what the repeat may do. The same rule links a parent step to its child run before the child can bill: a future transcript summary can repeat its `ncly agent run` call with the recorded ID and reuse a verified answer instead of paying twice. [Stripe's idempotency keys](https://docs.stripe.com/api/idempotent_requests) and the client token of Amazon EC2 make the same choice: the caller names the operation, a retry with the same name returns the first result, and the same name with other parameters is an error. Building every successful answer from the committed record makes the first and the repeated call answer alike, and printing it only after the completion write means that no caller sees a success that a repeated call would then refuse. Exit 75 promises that the same command is safe to repeat, so a repeated call after it runs the steps again instead of refusing them. Like Stripe, which compares the parameters of the incoming request, a call compares only what it states: comparing a value that preparation picked would turn the same call into `USAGE_INVALID` after one config edit, and leave only `ncly run view` to return the answer.

**Rejected.** A parent reference that the child records from its environment, the other option of M10, because finding the child then needs a scan of every record. Accepting a reused ID with other inputs, which would hand a caller the result of another call. Comparing resolved defaults, which one config edit would turn into a refusal of the same call. Saving the first answer as printed, because the repeated call may ask for another presentation, such as `--json`. Treating a repeat with the ID as permission to repeat an unknown effect, which [Inspection and explicit resume](../contract.md#inspection-and-explicit-resume) forbids. Repeating a child call whose record is missing, because the user may have deleted the record of a child that billed.
