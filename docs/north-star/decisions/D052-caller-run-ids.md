# D052 Let the caller name a run, so that a repeated call continues it

Decided 2026-10-12. A recorded command accepts `--run-id <id>`. A call whose ID no record holds starts a run under that ID. A call whose ID a record holds starts nothing new: it returns the saved result of a completed run, continues the run as `ncly run resume` would when the command supports resume, and otherwise answers `RESUME_UNSAFE`. A call whose command path, inputs, or ordered item keys differ from the record's fails with `USAGE_INVALID`. A step that starts a recorded command for its own work persists the child's ID with its intent, before the call, and repeats the call only while the child's record exists. [Run IDs](../contract.md#run-ids) holds the rules.

**Why.** An agent's shell can kill `ncly` or lose its answer, and the answer held the only copy of the run ID. Recovery then meant searching `ncly run list` by command path, item key, and start time, and a fresh session could find several candidates or none. A caller that chose the ID before the call still knows it after any loss: `ncly run view <id>` finds the run at once, and repeating the same call is safe, because the record decides what the repeat may do. The same rule links a parent step to its child run before the child can bill: after a lost answer, transcript repeats its `ncly agent run` call with the recorded ID and gets the saved answer instead of paying for a second one. [Stripe's idempotency keys](https://docs.stripe.com/api/idempotent_requests) and the client token of Amazon EC2 make the same choice: the caller names the operation, a retry with the same name returns the first result, and the same name with other parameters is an error.

**Rejected.** A parent reference that the child records from its environment, the other option of M10, because finding the child then needs a scan of every record. Accepting a reused ID with other inputs, which would hand a caller the result of another call. Treating a repeat with the ID as permission to repeat an unknown effect, which [Inspection and explicit resume](../contract.md#inspection-and-explicit-resume) forbids. Repeating a child call whose record is missing, because the user may have deleted the record of a child that billed.
