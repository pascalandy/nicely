# D047 Keep a program that may read the terminal in the process group of ncly

Decided 2026-10-10. The program runner starts each program in its own process group, except a program that may read the terminal, which stays in the process group of `ncly`: an extension, and an install command that doctor runs after a yes. A program can therefore receive the same signal more than once, and it treats a repeat during its cleanup as no new event. [Programs that ncly runs](../contract.md#programs-that-ncly-runs) holds the rules.

**Why.** The terminal sends Ctrl-C to its foreground process group, and a process outside that group stops with SIGTTIN when it reads the terminal. Docker moved its CLI plugins to their own process group in January 2024 and [reverted it three days later](https://github.com/docker/cli/commit/26560ff93c42cfe8237bb0ba40cdf349fcf7d812), because plugins that read the terminal hung, as [moby#47073](https://github.com/moby/moby/issues/47073) reports. An extension asks through its forms from M07, and `sudo` asks for a password, so both must keep the terminal. A program that never reads it, such as transcript's Python program, a harness that gets its task on stdin, or a version probe, keeps its own group, so a Ctrl-C reaches it once, through the program runner. `ncly` still finds every descendant through its parent process, as [D031](D031-cancel-process-tree.md) decides, so the process group never limits what cleanup reaches.

**Rejected.** Every program in its own process group, the first rule, for the reason above. Handing the terminal's foreground to the extension's group, as a shell does with `tcsetpgrp`, because `ncly` would no longer receive the Ctrl-C, so it could not stop an extension that ignores it.
