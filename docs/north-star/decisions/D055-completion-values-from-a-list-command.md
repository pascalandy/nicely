# D055 Complete an extension's values from its own list command

Decided 2026-10-13. An argument or a flag in a manifest may declare `values_from`: a list command of the same extension, the key of its answer that holds the values, and the field to suggest, such as `skill list`, `skills`, and `name` for the skill name of `ncly skill view`. Completion runs that command with `--json`, kills it when it outlasts 2 seconds, and suggests what it finds. A failure suggests nothing. `values_from` only suggests and never restricts what the command accepts. [Completion values](../contract.md#completion-values) holds the rules.

**Why.** Only the extension knows values such as its skills or its profiles, and a list command already answers them for agents, so completion reuses that answer instead of a second path to the same data. Core calling a command that an extension declares is no hook, as [D044](D044-additive-extensions.md) says, and it works for an extension in any language, because it needs nothing beyond the contract. Only a command whose verb is `list` qualifies, so a Tab never runs a command that writes, and core may kill it at the limit instead of waiting for its cleanup. The command still validates its own input, so a value that completion missed, such as a skill added a second ago, still works.

**Rejected.** Forwarding Cobra's `__complete` protocol to the extension, which every extension would have to implement, shell ones included, and which would make Cobra's protocol part of the wire contract. Static values in the manifest, which cannot list what the user configures or installs. A cache of values, which goes stale.
