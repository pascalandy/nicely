# D056 Let an extension add doctor checks through its status command

Decided 2026-10-13. An extension adds its own checks to `ncly doctor` through `ncly <domain> status`, a report command that its manifest marks with `doctor = true`. Doctor runs it within its `--timeout` and lists its checks under the extension's component, and an agent may call it alone. A status command neither writes nor bills, so doctor kills it at the limit, as completion kills a list command. [Status command](../contract.md#status-command) holds the rules.

**Why.** Some checks need the extension's own code, such as the Python version that transcript's program needs or whether a browser's cookies can be read, and only the extension can run that code. A report command already answers checks in the shape that doctor lists, and the verb `status` already means "reports the current state". Core calling a command that an extension declares is no hook, as [D044](D044-additive-extensions.md) says, and it works for an extension in any language. The manifest marks the command, so doctor never starts a `status` command that reports something else, such as the hosts of a fleet, or that may be slow.

Serious CLIs split the same way. Homebrew, Flutter, and npm run the checks of their doctor inside their own process, from their own modules. A host whose plugins run as separate programs asks each plugin through a declared interface and reads its structured answer: Docker calls the `docker-cli-plugin-metadata` subcommand of each CLI plugin and reads its JSON, and Terraform asks each provider for its schema over the plugin protocol. Nicely's extensions are separate programs, so doctor follows Docker and Terraform. `requires.bins` stays in the manifest, because every extension checks its programs the same way, and doctor checks them even for an extension that cannot start.

**Rejected.** Checks that the manifest declares, such as a command line and the output it expects. A static description cannot read a config table or a browser's cookies, so it would grow into a small language of checks that core interprets, and anything beyond it would still need the extension's code. Running every `ncly <domain> status` without a mark, for the reason above. A hook that adds checks inside core, which D044 rejects.
