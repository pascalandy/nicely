# D023 Configure with a shared TOML file and a local one

Decided 2026-10-05, revised 2026-10-13. The shared config describes the setup the user wants, and the local config overrides it on one machine, as [contract.md](../contract.md#configuration) defines. `ncly` edits a config file only through a command whose job is to change the setup, and it keeps comments and formatting. An unknown key is a warning. The table named after an installed extension's domain belongs to that extension, and doctor checks its keys against those that the extension's manifest declares. Doctor checks no table named after a domain that is not installed on this machine. Nicely's own environment variables start with `NCLY_`.

**Why.** TOML is easy to read and edit, and Pascal's tools already use it. One shared file lets a new machine reach the same setup, for example with `ncly tap sync`. The local file keeps machine paths out of the shared one. A warning on unknown keys keeps older versions of `ncly` working. The manifest is static, so core knows the keys of an extension without starting it. A table for an extension that one machine lacks is no mistake in a config that travels, so the cost of skipping it is that a misspelled table name goes unreported.

**Rejected.** YAML. A warning for each table that no installed extension owns, which would flag the setup of another machine on every machine that lacks its extension. A config that only humans write, with Nicely's own records kept per machine, because each new machine would then need every tap added again.
