# D011 Check locally by default, test live on request, and install nothing

Decided 2026-10-05, revised 2026-10-13. `ncly doctor` stays on the machine by default. `--live` calls free endpoints only. Invalid config is a failed report finding on stdout, and independent checks still run. Doctor never installs anything, in any mode: the hint of a failed check holds the install command for this system, its `next` holds the same command as words, and the human runs it. Each program has one definition in the manifest, and [Required programs](../core-spec.md#required-programs) defines its optional metadata and how doctor checks it. Doctor never checks a program marked `conditional`, such as one harness among several. [ncly doctor](../core-spec.md#ncly-doctor) holds the rules.

**Why.** Doctor must be safe to run at any time. A live check proves a key works without a bill. A doctor that never installs never writes, so it needs no `--dry-run`, no confirmation, and no terminal for the password of `sudo`, and `ncly auth` stays the first command that writes. The human runs the install command either way, and the hint puts it one paste away. The manifest is static, so doctor checks the programs of an extension and gives their install commands without starting it, and the extension's author, who knows each package name, writes the commands. A probe whose arguments the manifest names covers a program that answers `-version` or `version` instead of `--version`. One definition per program keeps two commands from disagreeing about it. Only the extension knows which harness its config selects, so doctor leaves a conditional program to the extension.

**Rejected.** An install after a yes in a terminal, the first version of this entry, because it made doctor a command that writes, which then needs `--dry-run`, and an install command that asks for a password must keep the terminal, as [D047](D047-terminal-process-group.md) explains. An explicit `ncly doctor --install <check>`, because it adds a writing mode to a report command for a step that one paste already does. A command that doctor builds from one package name, because names differ between package managers. One install command per operating system, because it cannot tell Arch from Ubuntu. Failing every absent program that a command may run, which would fail a harness that no profile uses on every machine that lacks it.
