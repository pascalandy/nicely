# D037 Summarize a saved transcript as a new operation

Decided 2026-10-07. `ncly transcript summary run <run-id>` summarizes the verified transcripts of a saved run as a new recorded operation. `ncly run resume` never repeats a `summarize` step whose outcome is `unknown`, and the silent summary retries of the transcript CLI are gone. [transcript's spec](../../../extensions/transcript/spec.md#ncly-transcript-summary-run) holds the rules.

**Why.** A summary can bill, so a lost answer may already be charged. Resume never repeats that unknown request. A new operation records the verified transcript references in the evidence of each `summarize` step, without a `transcribe` step that it never ran, keeps its own prompt and profile, and writes a file named with its run ID. It leaves the source record valid and supports safe resume of its own never-started summary. Holding the source lock while it checks and records those references keeps it from racing its source executor, and releasing the lock before the first summary keeps a long summary from blocking the source. `--key` selects the items, so a new summary of one item never bills the others again. The caller explicitly chooses any new bill.

**Rejected.** Copying the transcript into the new run, which would need a retention rule for no gain, because a changed source transcript makes resume refuse and a new summary run reads the current text. A completed `transcribe` step copied into the new record, which would claim work that the run never did. A resume flag that overrides an unknown step, because `--force` never makes an unknown effect safe. Treating every summary as free, because some profiles bill per call. Rerunning the whole transcript, which bills Deepgram again.
