# D061 Install complete tap publications without a local build

Decided 2026-10-16. Pascal chose precompiled Go extensions for each supported system. A script that runs as published stays in Git. Each archive carries its executable, manifest, catalogs, and skill together. The official tap stays in the Nicely repository, as [D041](D041-first-party-extensions.md) decides. It follows the installed `ncly` release tag. Other precompiled taps follow their latest stable release, subject to the existing manifest contract check.

A tap ID includes its host and maps to local storage through its full SHA-256 hash. Config edits use `tomledit`. Each tap publishes one immutable tree, selected by an atomic link replacement. Calls select that tree once, before reading a manifest. Ownership evidence and durable intent permit recovery without repeating an unverified effect. [ncly tap](../core-spec.md#ncly-tap) holds the formats and rules. [D058](D058-grants-by-path.md) defines the grant source.

**Why.** [`gh extension install`](https://cli.github.com/manual/gh_extension_install) installs precompiled release artifacts or a repository's executable script. Nicely follows that distribution model. Its users need no compiler. Keeping the official release aligned with core avoids an independent upgrade that core may reject. The manifest already checks the public contract. [`tomledit`](https://github.com/creachadair/tomledit) edits TOML structure while retaining comments and whitespace. Immutable publications extend D035's complete-destination rule to the interval between manifest loading and process launch.

**Rejected.** Building on the user's machine. Installing first-party extensions through Homebrew. A second compatibility version beside `contract_version`. Replacing the executable, manifest, catalogs, and skill separately. Holding a reader lock that blocks sync throughout an extension's execution. Treating a matching domain or path alone as proof of tap ownership.
