# D057 Settle the edge cases of ncly auth with gh, Docker, and clig.dev

Decided 2026-10-13. `ncly auth login` removes the whitespace around a key, typed or piped, and refuses an empty one. `--stdin` refuses a terminal on stdin. `ncly auth logout` of a service without a stored key answers `NOT_FOUND`. `ncly auth status` lists only the services that installed extensions declare, and fails with exit 78 when one of them has no key, as `ncly doctor` does. [ncly auth](../core-spec.md#ncly-auth) holds the rules.

**Why.** `gh auth login --with-token` trims the whitespace around the token that it reads, and `docker login --password-stdin` removes the final line ending, so both accept the output of `echo` or of a secret store. An API key never starts or ends with whitespace, so Nicely trims as `gh` does. Both refuse an empty secret. clig.dev asks a command that expects piped input not to wait on a terminal, and a key typed there would show, so `--stdin` refuses it and the hint offers the prompt, which turns echo off as clig.dev asks of a password prompt. `gh auth logout` fails for a host without a login, as `kubectl delete` fails for what does not exist. The end state is the same either way, and the failure shows a mistyped service, which `status` never lists. `gh auth status` exits 1 when a host has no valid login, so the exit code alone tells a script that a human must log in, and `status` agrees with doctor. `status` reads one entry per declared service and lists no other, because listing the keychain's entries would dump the whole default keychain on macOS, through `security dump-keychain`, and parse its text, which is slow and fragile, and because an agent needs the services that installed extensions depend on.

**Rejected.** Docker's narrower rule, which keeps any whitespace but one line ending, because Docker reads opaque passwords, while an API key holds no whitespace. Docker's success for a logout without a stored key, because it hides a mistyped service. Reading a terminal on `--stdin`, as `gh` and Docker do, which shows the key as the human types it, or waits on an agent's pseudo-terminal. The exit 0 of `gh auth status --json` whatever the logins, because `ok` and the exit code agree in every mode, as [Output](../contract.md#output) requires. `ok: true` for a missing key in `status`, the first version of its section, because `status` and doctor then gave one key two verdicts. Listing the services that hold a key beside the declared ones, because every `status` on macOS would then dump the whole default keychain.
